# Архитектура

## Поток выполнения

```text
плагин.dgplugin
       │
       ▼
DevGramPlugins.java ── установка, состояние, Android и Telegram API
       │
       ▼
devgram_plugins.py  ── проверка архива, импорт, реестр, события
       │
       ▼
BasePlugin          ── публичный API для кода плагина
       │
       └──────────────► вызовы обратно в DevGramPlugins.java
```

## Слои

### Публичный Python API

Пакет `devgram` — поверхность API, которой пользуется автор плагина. Главный
класс — `BasePlugin`. Вспомогательные модули дают доступ к интерфейсу,
форматированию текста, интентам, файлам, Telegram-контроллерам и Dev Server.

### Python runtime

`devgram_plugins.py` принадлежит приложению, а не плагину. Он:

- проверяет манифест и совместимость;
- безопасно разбирает пути внутри ZIP;
- подключает упакованные Python-зависимости;
- находит наследника `BasePlugin`;
- хранит экземпляры и состояние включения;
- передаёт события, запросы, обновления и нажатия меню;
- выгружает модули и хуки при перезагрузке.

### Нативный Android runtime

`DevGramPlugins.java` запускает Python runtime через Chaquopy и связывает его с
Telegram Android. Здесь реализованы отправка сообщений и файлов, UI, хранилище,
Android intent API, хуки Java-методов, pill/panel API и управление плагинами.

`DevGramDevServer.java` слушает только `127.0.0.1`. Компьютер получает доступ
через `adb forward`, передаёт токен в заголовке и может загрузить пакет,
перезапустить плагин или подключить отладчик.

## Жизненный цикл

1. DevGram находит одиночные `.py` и установленные `.dgplugin`.
2. Runtime читает метаданные и создаёт отдельный Python-модуль.
3. Найденный наследник `BasePlugin` создаётся и получает свой идентификатор.
4. Для включённого плагина вызывается `on_load()`.
5. События приложения передаются только в нужные обработчики.
6. При выключении или перезагрузке вызывается `on_unload()`, снимаются нативные
   хуки и очищаются импортированные модули пакета.
