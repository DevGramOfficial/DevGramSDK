# Нативный мост

## Почему это Java-код

Плагин выполняется в Python, но интерфейс, Telegram-контроллеры и жизненный цикл
Android находятся в JVM. `DevGramPlugins.java` является общей точкой входа для
обоих миров: Python вызывает его методы через `java.jclass`, а Java вызывает
функции `devgram_plugins.py` через Chaquopy.

## Основные группы API

- запуск runtime, загрузка, включение и перезагрузка плагинов;
- отправка текста, форматированного текста, фото и файлов;
- Telegram account/controller API;
- clipboard, файлы плагина и постоянное хранилище;
- меню сообщений и ссылок;
- настройки, alert и bulletin UI;
- pill stack и вкладки панели вложений;
- Android intents;
- перехват Java-методов и очистка хуков;
- локальный Dev Server и удалённый Python debugger.

Один класс исторически также содержит код экранов каталога и модерации. Он
оставлен целиком, чтобы опубликованный исходник совпадал с кодом приложения и не
создавал ложного впечатления о поведении runtime.

## Зависимости

Этот код компилируется как часть DevGram и использует:

- Android SDK;
- классы `org.telegram.*`;
- Chaquopy (`com.chaquo.python.*`);
- NanoHTTPD;
- нативный механизм Java-хуков приложения.

Поэтому два Java-файла нельзя скопировать в пустой Android-проект и собрать без
остальных зависимостей. Для автора обычного плагина их сборка не требуется.

## Dev Server

Сервер привязан к `127.0.0.1`, а не к сетевому интерфейсу телефона. Типичная
схема подключения:

```text
Builder/CLI → localhost на ПК → adb forward → localhost телефона → DevGram
```

Запрос должен содержать токен Dev Server. Токен можно сбросить в приложении;
после сброса старый токен перестаёт работать.
