# Формат `.dgplugin`

`.dgplugin` — обычный ZIP-архив с обязательным `manifest.json`.

Минимальная структура:

```text
example.dgplugin
├── manifest.json
└── main.py
```

Пример манифеста:

```json
{
  "id": "example.plugin",
  "name": "Example",
  "version": "1.0.0",
  "author": "Developer",
  "description": "Описание плагина",
  "main": "main.py",
  "min_devgram": 3
}
```

## Поля runtime

| Поле | Назначение |
| --- | --- |
| `id` | Постоянный идентификатор плагина. |
| `main` | Точка входа относительно корня архива; по умолчанию `main.py`. |
| `min_app_version` | Минимальная версия приложения DevGram. |
| `min_devgram` / `min_sdk` | Минимальный уровень API плагинов. |
| `requirements` | Список зависимостей, которые должны быть вложены в пакет. |

Поля каталога, локализации, ресурсов и сборки подробно описаны в
[официальной документации](https://docs.devgram.space/docs/builder).

## Проверки при установке

Runtime проверяет, что:

- архив является корректным ZIP и содержит не более 4096 записей;
- нет повторяющихся имён, абсолютных путей и выхода через `..`;
- существует `manifest.json` и указанная точка входа;
- `id` содержит только буквы, цифры, `.`, `_`, `-` и не длиннее 64 символов;
- требования имеют допустимый формат и присутствуют внутри пакета;
- текущая версия приложения и уровень API соответствуют манифесту.

Для создания и проверки пакета используется
[DevGram Builder](https://github.com/DevGramOfficial/DevGramBuilder).

## Распаковка и анализ

Внешний `.dgplugin` распаковывается как ZIP. В репозитории SDK есть безопасный
инструмент, который проверяет пути и не позволяет архиву записать файлы за
пределы выбранного каталога:

```bash
python3 tools/dgplugin.py unpack example.dgplugin
```

После `dgb build -c` Python-файлы находятся в пакете в виде байткода `.pyc`.
Для него доступно дизассемблирование на совместимой версии Python:

```bash
python3.11 tools/dgplugin.py decode example.dgplugin
```

Результат сохраняется в файлах `.pyc.dis.txt`; это представление инструкций
байткода, а не точное восстановление исходного текста.

## Защищённые исходники

DevGramBuilder поддерживает AES-128, AES-192 и AES-256. Такой пакет содержит
обычный манифест, ресурсы и исполняемый `.pyc`, поэтому устанавливается в
DevGram без пароля. Точные авторские `.py` находятся во вложенном контейнере
`.devgram/protected-sources.zip`.

Для восстановления исходников на ПК нужен `pyzipper` и пароль автора:

```bash
python3 -m pip install pyzipper
python3 tools/dgplugin.py unpack protected.dgplugin
```

Если пароль не указан через `-p` или `DEVGRAM_PLUGIN_PASSWORD`, CLI запросит его
без отображения введённых символов. Сам DevGram пароль не запрашивает и не
хранит.
